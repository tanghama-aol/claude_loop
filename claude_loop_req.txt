## Web 版多 Agent 任务循环执行平台

将原来的 `claude_loop.sh` 单脚本循环调用能力，改造成一个可视化 Web 应用。应用用于配置不同 AI Agent 的运行方式，拆解用户需求为任务目标文件，并按任务独立调用对应 Agent 执行，直到任务完成、全部完成或触发退出条件。

### 1. Agent Profile 配置

系统支持配置多种 Agent 类型，包括：

- Gemini
- Claude
- Codex

同一种 Agent 可以创建多个 Profile。每个 Profile 由以下内容组成：

- Profile 名称，例如 `claude-default`、`codex-fast`、`gemini-review`
- Agent 类型
- 工作目录默认值
- 环境变量配置，例如 API Key、模型名、代理地址等
- 运行命令，例如 `claude`、`codex`、`gemini`
- 命令参数，例如 `--dangerously-skip-permissions`、`--model xxx`
- Prompt 模板
- 无需用户介入的选项，例如自动确认、跳过交互、非交互模式、最大重试次数

Profile 应支持新增、编辑、复制、删除、启用和禁用。敏感环境变量在界面中应隐藏显示。

### 2. 任务需求输入与目标文件生成

用户可以在 Web 页面输入原始任务需求，并选择一个 Agent Profile 进行任务拆解。

系统根据用户输入生成任务目标文件，例如：

```text
P3-真实笔顺评分.md
```

生成后用户可以在页面中编辑该目标文件。目标文件用于后续 Agent 执行，每个任务项应包含任务描述、状态、执行记录和完成标记。

任务拆解 Prompt 要求：

```text
请根据用户需求拆解可执行任务，写入目标任务文件。
每个任务应可独立执行，并包含明确完成标准。
不要直接执行任务，只生成或更新任务列表。
```

### 3. 任务执行循环

用户可以为每个任务选择不同的 Agent Profile 并启动执行。系统按任务调用对应 Profile 的命令，Prompt 示例：

```text
1. 从 ${目标任务文件} 获取一条任务进行工作，完成后将任务标记为完成。不要启动子 agent，直接在当前 agent 中完成。
2. 成功完成后修改 ${目标任务文件}，失败则不修改，并输出错误。
3. 如果任务完成，则输出 "任务完成"。
4. 如果目标文件中任务全部完成，则输出 "全部任务完成"。
```

执行规则：

- 输出包含 `429` 时，等待 5 分钟后重试。
- 输出包含 `任务完成` 时，等待 10 秒后继续下一轮。
- 输出包含 `全部任务完成` 时，停止该任务循环。
- 其他输出时，等待 1 分钟后重试。
- 如果连续 3 次输出完全相同，且目标任务文件没有变化，则停止该任务循环。

### 4. 日志与运行状态监控

Web 页面应展示所有任务的运行状态，包括：

- 未开始
- 运行中
- 等待重试
- 已完成
- 全部完成
- 已停止
- 执行失败

每个任务应展示：

- 当前使用的 Agent Profile
- 工作目录
- 最近一次启动时间
- 最近一次退出码
- 最近输出摘要
- 完整执行日志
- 重试次数
- 任务文件修改时间

日志应按任务隔离保存，并支持实时刷新、搜索、复制和下载。

### 5. 多目录与隔离运行

系统支持配置多个工作目录。每个任务可以选择不同目录和不同 Agent Profile 执行。

隔离要求：

- 不同任务的进程互不影响。
- 不同任务的日志互相隔离。
- 不同任务可以同时运行。
- 停止某个任务时，不影响其他任务。
- 每个任务只能访问其配置的工作目录。

### 6. 基础页面

Web 应用至少包含以下页面：

- Agent Profile 管理页：管理 Gemini、Claude、Codex 的运行配置。
- 任务创建页：输入需求、选择拆解 Profile、生成目标任务文件。
- 任务编辑页：查看和编辑目标任务文件。
- 任务运行页：选择执行 Profile、启动、暂停、停止和重试任务。
- 日志监控页：查看任务状态、实时日志和历史执行记录。

### 7. 安全与配置

- 敏感环境变量不得明文展示。
- 执行命令前应展示最终命令摘要。
- 高风险参数需要在 Profile 中显式配置。
- 默认不允许任务访问未配置的目录。
- 应记录每次任务启动、停止、失败和完成事件。
